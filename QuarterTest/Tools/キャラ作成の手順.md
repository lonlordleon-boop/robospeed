# キャラ作成の手順とハマりどころ

「きまぐれマイベイビィ」の3Dキャラを作るまでの流れ。
2026年9月、女の子1人目（girl_v46）を作り上げるまでに分かったことをまとめてある。
2人目以降や別キャラを作るときは、これを読んでから始めること。

道具はすべて `Tools/blender/` にある。実行はどれもこの形。

```bash
"/c/Program Files/Blender Foundation/Blender 5.2/blender.exe" -b --factory-startup -P 道具.py -- 引数...
```

---

## 1. 全体の流れ

| 段階 | やること | 道具 | 費用 |
|---|---|---|---|
| 1 | 三面図（正面・横・後ろ）を1枚の絵で用意する | ユーザーが描く | — |
| 2 | 3枚に切り分けてアップロード | 手作業 | — |
| 3 | 3枚からモデルを生成（テクスチャ・リグ・アニメ付き） | `multi_image_to_3d` | 38クレジット |
| 4 | テクスチャを三面図で貼り直す | `meshy_v5_retexture` | 9.5クレジット |
| 5 | 骨・重み・アニメを貼り直し前のモデルから写す | `transferrig2.py` | — |
| 6 | 形と重みの修正（下の「6. 修正の順番」） | 各種 | — |
| 7 | 表情の絵を作る | `eyeclose.py` `mouth3d.py` | — |
| 8 | テクスチャの縁を塗り広げて FBX 化 | `texpad.py` `to_fbx.py` | — |
| 9 | 色替えで人数分そろえる | `recolor.py` | — |

3の生成は Higgsfield 経由の Meshy。`generate_3d` に
`should_texture` `enable_rigging` `enable_animation` `animation_action_id:30`
`pose_mode:"a-pose"` `rigging_height_meters:1.2` `target_polycount:30000` を渡す。

## 2. 最初に知っておくべき3つの事実

**貼り直し（retexture）は形を変えない。**
三面図の髪型を変えても、貼り直しでは絵が変わるだけでモデルの形は1ミリも動かない。
形を変えたいなら3の生成からやり直す。ここを説明せずに9.5クレジット使わせた失敗がある。

**生成そのままのテクスチャは眠い。**
`multi_image_to_3d` が焼くテクスチャは平坦で質が低い。
`meshy_v5_retexture` に三面図を `image_style_url` として渡すと、陰影の入った絵になる。
髪の筋も顔の陰影も、実物は形ではなくこの絵で表現されている。

**テクスチャは面ごとにバラバラに並んでいる。**
Meshy の貼り直しが吐くテクスチャは、三角形ひとつずつが小さな断片として散らばった配置。
画像を開いて「目のあたり」を探すことはできない。
だから絵の修正は、画素ごとに「モデルのどこに当たるか」を計算して位置で塗る。
`eyeclose.py` `mouth3d.py` `recolor.py` `boxpaint.py` はどれもこの方式。

---

## 3. 貼り直しのあとに骨を戻す方法

貼り直したモデルには骨もアニメも入っていない。頂点の数も少し変わる。
ただし**頂点の位置は完全に一致する**ので、位置で照合すれば重みをそのまま写せる。

```bash
transferrig2.py -- 今の.glb 貼り直した.glb 出力.glb
```

近さで写すと A字ポーズでは手と腿が近いため、手に腿の重みが乗って壊れる。
必ず位置の完全一致（KD木）で照合すること。

別の体へアニメだけ移したいときは `animgraft.py`。骨の名前で対応を取る。
Meshy の自動リグは骨の名前も素の姿勢もほぼ同じなので、これで移せる。

---

## 4. 座標の決まりごと（毎回ここで間違える）

- **glTF ファイルの中**は Y が上。`sidefix.py` `rebake.py` など glb を直接読む道具はこちら。
- **Blender に読み込んだあと**は Z が上。`zoom3d.py` など Blender を通す道具はこちら。
- 換算は `Blender(x, y, z) = glTF(x, -z, y)`、逆は `glTF = (bx, bz, -by)`。
- **Blender の画像の画素は下の行が先頭**。UV の v はそのまま行番号に使う。
  上下を反転して書くと、まったく別の場所を塗る。これで髪に赤い点を付けた失敗がある。

位置が合っているか自信がないときは `zband.py` で決まった高さに色の帯を焼き、
描いて確かめる。目の高さも口の高さも、これで確定させた。

## 6. 修正の順番（この順でないと壊れる）

```bash
sidefix.py     -- 入力.glb 出力.glb                      # 靴の左右をつながりで分ける
rebake.py      -- 入力.glb 出力.glb 1.33 0.022 0.03      # 胴を伸ばす・肩を下げる・脚を開いて焼き直す
spread_legs.py -- 入力.glb 出力.glb 2 Idle               # 立ち姿だけ脚を開く
rollfilter.py  -- 入力.glb 出力.glb Walk_Child 0.3 Spine02,Spine01,Spine,neck,Head
hairfix.py     -- 入力.glb 出力.glb                      # 髪の重みを頭へ寄せる
liftdip.py     -- 入力.glb 出力.glb クリップ名           # 全クリップに掛ける（下記）
```

数値は1人目の体つきに合わせたもの。体が変われば調整が要る。

**床合わせは全クリップに掛けること。**
歩きにしか掛けていなかったせいで、スキップは7.6cm、走りと大人歩きは12〜13cm
地面にめり込んだまま出荷しかけた。`floor.py` で全クリップを測って確認する。

```bash
floor.py -- 入力.glb クリップ名 24
```

最低点が +0.1〜+0.3cm なら正しい。マイナスならめり込んでいる。

## 7. 動きを作る

歩きは、スキップを0.4倍に縮めたものを使っている。

```bash
scaleclip.py   -- 入力.glb 出力.glb Skip 0.4 Walk_Child  # 振りを0.4倍にして歩きへ入れる
spread_arms.py -- 入力.glb 出力.glb -20 Walk_Child       # この歩きだけ腕を閉じる
liftdip.py     -- 入力.glb 出力.glb Walk_Child           # 床に合わせる
spread_legs.py -- 入力.glb 出力.glb 5 Walk_Child         # 靴が近すぎるので開く
```

`scaleclip.py` は平均の姿勢へ寄せることで振りだけを小さくする。
新しい入れ物を作って書くので、元のスキップは壊れない。

腕全体の開きは `spread_arms.py` をクリップ指定なしで掛ける（素の姿勢にも焼き込まれる）。
現行は +5度。

## 8. 表情

絵は1枚しか貼れないので、表情ごとに丸ごと1枚用意して差し替える。
まばたきと口は同時に動かない（`FaceBlink.cs` が順番待ちさせている）。

| ファイル | 中身 |
|---|---|
| `girl_tex_pad.png` | ふだんの顔 |
| `girl_tex_blink.png` | 目を閉じた顔 |
| `girl_tex_mouth.png` | 口を閉じた顔 |

```bash
eyeclose.py -- 入力.glb 出力.png 0.098,-0.27,0.788 0.082,0.070,0.078 0.762 0.014 0.010
mouth3d.py  -- v40.glb 先.glb 出力.png -0.07,0.07,-0.40,-0.24,0.58,0.75 0.003
```

`eyeclose.py` は目の範囲をまわりの肌色で塗りつぶし、閉じたまぶたの弧を描く。
肌色は「まわりの画素のうち、まん中の色から離れていないもの」の平均を使う。
外れ値を落とさないと灰色の筋が出る。

**顔の形は触らないこと。**
目のまわりをならすと瞳の絵が崩れる。顔ごとならすと目も髪も壊れる。両方試して両方だめだった。

## 9. 色替え

```bash
recolor.py -- 入力.glb 出力.png "箱|色相下限,上限|新色相,鮮やか倍率,明るさ倍率,鮮やか下限,面まとめ割合,面まとめ下限,ばらつき残し"
```

1人目の設定（`;` でつないで3つ同時に渡す）:

| 部位 | 箱 | 色相の窓 |
|---|---|---|
| シャツ | `-0.30,0.30,-0.35,0.35,0.33,0.62` | `0.975,0.022` |
| パンツ | `-0.25,0.25,-0.25,0.10,0.18,0.42` | `0.55,0.72` |
| ランドセル | `-0.30,0.30,-0.35,0.35,0.28,0.72` | `0.085,0.20` |

**肌は「赤っぽい」。** 色相は 0.04〜0.09、鮮やかさ 0.3 前後。服の赤は色相 0.98〜0.02、鮮やかさ 0.87。
色相の窓を広く取ると腕に斑点が出る。窓は狭く、鮮やかさの下限で分ける。

**境目の画素は取り残される。** 赤と黄が混ざった画素は色相が中間になり、紐のふちに赤線が残る。
面まとめ割合（0.15）を指定すると、面ごとに「服か」を先に判定し、服の面なら窓を広げてまとめて塗る。
肌の面にははっきりした服の色が無いので除外され、斑点は出ない。

**暗い色・渋い色にするときは「ばらつき残し」を 0.3 に。**
面のふちの画素はもともと少し暗く鮮やかさも低い。倍率だけ掛けるとその差が目立ち、
三角形の網目模様が浮き出る。素材の標準色へ寄せると消える。

塗り替えたあとは必ず `texpad.py` を掛けてから `swaptex.py`。縁の塗り広げを忘れると継ぎ目が出る。

## 11. 見た目の確認

数字だけで判断しないこと。必ず描いて見る。

```bash
views.py       -- 入力.glb 出力.png クリップ名 0.0,0.25,0.5,0.75   # 正面・後ろ・横 × コマ
zoom3d.py      -- 入力.glb 出力.png x,y,z 幅 方位角,仰角[;...]      # 寄り（影なし）
headsweep2.py  -- 入力.glb 出力.png -30,0,30 0 FLAT                # 顔を角度違いで
```

`zoom3d.py` は影なし（FLAT）。`light='STUDIO'` に変えた版を作れば影ありで比べられる。
**テクスチャの汚れか、面のうねりの影か**は、この2つを見比べれば分かる。

手足と胴のうねりは `meshsmooth.py` でならせる。頭と靴は守ること。

```bash
meshsmooth.py -- 入力.glb 出力.glb 2 "0.58,1.30;0.00,0.16"
```

## 12. 別キャラを作るときの見積もり

- 三面図1枚。ユーザーが用意する。
- 生成 38クレジット。テクスチャが眠ければ貼り直し 9.5クレジット。
- 修正の手順はスクリプト化済み。体つきが変われば数値の調整が要るが、作り直しではない。
- アニメ5本は `animgraft.py` で移せる。
- 顔の表情は、目と口の位置を `zband.py` で測り直すところからやる。

同じキャラの色違いなら、生成もクレジットも要らない。`recolor.py` の数字を変えるだけで数分。

## 13. Unity 側

- `Assets/Resources/Models/girl_fbx.fbx` … `to_fbx.py` で glb から書き出したもの。
- `Assets/Editor/ModelImportSettings.cs` … 取り込み設定。テクスチャは非圧縮。
  UV の島が余白なしで詰まっているため、圧縮すると髪に肌色がにじむ。
- `Assets/Scripts/Model3DBoot.cs` … 材質を直し、表情の絵を渡す。
  glTFast が金属度の指定を読み違えるため、金属度0・つや低めに上書きしている。
- `Assets/Scripts/FaceBlink.cs` … まばたきと口の差し替え。
- 別キャラは `Models/キャラ名_fbx.fbx` と `Models/キャラ名_tex_pad.png`（表情があれば `_tex_blink` `_tex_mouth`）を置き、
  `Model3DBoot.cs` の `BuildCharacter` で作る。実行中は Tab で元気少女と入れ替わる（新お嬢様＝`ojou`）。

表情が3枚あるので、4人ぶんだと 2048 のテクスチャが12枚になる。
非圧縮のままだと重い。実際に画面へ出す大きさを見て 1024 に落とすことを勧める。

## 14. 元気少女（v55）の顔で別キャラを作る

2026年9月、新お嬢様で「綺麗になった」と認められた順番。秀才など次のキャラもこの順で作る。

**三面図**は、髪と服だけを描き替えた「のっぺらぼう＋鼻」。目・眉・口は描かない。
v55 の目・口・眉は、あとからステッカーとして貼る（`partpaste.py`、位置は preview.html の福笑いで決める）。

### 生成と貼り直し（クレジットを使うのはここだけ）

| 段階 | 道具 | 費用 |
|---|---|---|
| 生成 | `multi_image_to_3d`（1章と同じ指定） | 38クレジット |
| 貼り直し | `meshy_v5_retexture` | 9.5クレジット |

貼り直しは三面図だけを渡すと、描き込みが眠く、変な色も乗る（首の黄色、紺のボタン列）。
**三面図に加えて `text_style_prompt` と `enable_pbr: false` を必ず付ける。**
新お嬢様で使った文章:

```
Match the reference sheet exactly. The face is blank fair skin with soft pink cheeks only:
no eyes, no eyebrows, no mouth. The hair is solid glossy black: never paint any skin-coloured
stroke on top of the hair or the bangs. The neck is plain skin colour. The cardigan is pure white
with small white buttons; navy is used only for the hair bow, the collar ribbon, the skirt line and the shoes.
```

髪の色、服の色、その色を使う場所はキャラごとに書き替える。

### 形と動き

```bash
transferrig2.py -- 生成.glb 貼り直し.glb a1.glb
sidefix.py      -- a1.glb a2.glb                          # 靴の左右を分ける（すき間 0.2〜2.3% → 2.2〜4.5%）
rebake.py       -- a2.glb a3.glb 1.33 0.022 0.03
animretarget.py -- a3.glb girl_v55の直した版.glb r.glb Idle,Run,Skip,Walk_Adult,Walk_Child,Wave
floorzero.py    -- r.glb g0.glb
liftdip.py      -- （Idle〜Wave の全クリップに1本ずつ）
liftdip.py      -- （Run〜Wave に 0.12 down を1本ずつ）
meshsmooth.py   -- 入力.glb s1.glb 2 "0.58,1.35;0.00,0.14;0.15,0.35"   # 頭・靴・スカートを守る
facesmooth.py   -- s1.glb s2.glb -0.17,0.17,0.62,0.88,0.12 0.030 "" n  # 顔の前面は法線だけならす
```

- 動きは `animgraft.py` ではなく **`animretarget.py`** で移す。骨の向きが違うので、animgraft だと体が傾く。
- 元にする v55 は、右手首を直したあとの版を使う。そうすれば `mirrorbone.py` は要らない。
- **髪が長いキャラには `hairfix.py` を掛けない。**
  首の高さで頭の重みを外すため、そこで髪が裂ける（待機の伸びた辺 0本 → 37本）。
  外しても走りの見た目は変わらなかった。
- `meshsmooth.py` でスカートを守らないと、プリーツの裾が波打つ。

### 絵の仕上げ

```bash
skinmatch.py -- s2.glb m1.png m1.glb 1.0,0.824,0.718                                 # 肌を三面図の色へ（← 手本の赤 1.0 は危ない。下の落とし穴を読むこと）
lineerase.py -- m1.glb e1.png -0.07,0.07,0.67,0.75,-0.10 0.06                         # 貼り直しが描いた口の線を消す
recolor.py   -- e1.glb c1.png "-0.035,0.045,-0.40,-0.02,0.27,0.495|0.55,0.72|0.60,0.0,2.4,0.15,0.15,0.05,0.3"  # 紺のボタン列を白へ
whitefix.py  -- c1.glb c2.png "-0.030,0.040,0.27,0.492;-0.008,0.012,0.492,0.512" -0.02 0.12  # 白の塗り残し
mouthpaste.py -- c2.glb 元気少女の鼻.png n1.png 出力.glb -0.0013,0.7697 0.0539 0.0539 "" "" NEWMESH
blush.py     -- n1.glb b1.png 0.13,0.74 0.030,0.020 0.895,0.88                          # 頬の赤み
partpaste.py -- b1.glb 部品.json p2.png 出力.glb                                        # 目・口・眉
texpad.py    -- p2.glb p2.png pad.png
swaptex.py   -- s2.glb pad.png 仕上げ.glb
timezero.py  入力.glb 出力.glb Idle,Run,Skip,Walk_Adult,Walk_Child,Wave
```

- 秀才少女で分かったこと（2026年9月）
  - **赤い服があるキャラは、`skinmatch.py` に色相と明るさの窓を渡す**（`0.012,0.028 0.55,0.62`）。
    - 渡さないと、くすんだ赤チェックも肌と判定されて、明るいピンクに変わる。
    - 位置の箱で外す方法は、スカートの下の腿まで外れて色の段差が出たので使わない。
  - **目・口・眉の位置は、前のキャラの値を換算して初期値にする。**
    - 同じ縮尺で正面を描き、あごの高さ・前髪の下端・顔の幅・頬の赤みの中心を測る。
    - 換算は `z新 = あご新 + (z旧 − あご旧) × 縦の比`、`x新 = x旧 × 横の比`、`幅新 = 幅旧 × 比`。
    - 秀才少女は縦1.08・横1.06で、頬の赤みの位置がぴったり一致した。
  - 貼り直しが頬の赤みを残した場合は `blush.py` も `lineerase.py` も要らない。絵を見て決める。
  - 髪がボブでも `hairfix.py` は伸びた辺を増やした（走り 264 → 343 本）。掛けない。
  - **スキップで顔がぐにゃぐにゃ歪んだ。** 顔に腰や腕の重みが混ざっていた。`facewarp.py` で測ると、スキップで最大2.94cm崩れていた（元気少女は0.10cm）。
    - `headclean.py -- 入力 出力 0.02 "" 0.06`（首の関節の2cm上から6cmかけて頭だけへ）で0になった。
    - 余裕0・幅4cmだと、首まわりの伸びた辺が待機で70本に増えた。
    - 伸びた辺の数だけでは顔の歪みは分からない。仕上げたら必ず `facewarp.py` を測る。
  - **ランドセルが腕に引っ張られてゆがんだ。** `bindpart.py` で、背中側の本体を胴の骨の平均の重みへ付け直した。
    - コマンド: `bindpart.py -- 入力 出力 AUTO "-0.12,0.12,0.35,0.55,-0.32,-0.20" "9,-0.12" 4`
    - 胸の骨1本に固定したり、肩ベルトまで含めたりすると、ベストや腕との境目が裂けた（走りの伸びた辺 733〜1614本）。
    - 境目の4周は、元の重みから段々に切り替える。

    - 新お嬢様は色が鼻先の約12mm上にあり、逆になっていた。直すときは色ではなく**鼻の形（ポリゴン）の方を動かす**。
    - 測り方: `noseline` で顔の真ん中の縦の線に沿って、表面の前後の位置と絵の赤みを1mm刻みで出す（スクラッチの道具）。
    - `mouthpaste.py` に渡した中心と、実際の色の中心はずれる（元気少女の鼻.png は約4mm上に寄っている）。必ず貼ったあとの色を測る。

    - 手本はギャル少女の完成版の glb。0.004,0.8148 はギャル少女の鼻先。顔の幅の比は facewidth の値（芸術・わんぱくは 0.94）。

    - glb を直接書き換えるので、骨・動き・絵は変わらない（timezero.py は要らない）。
  - 途中でつまずいたこと（道具の中に直してある）
    - 手本の三角形の上で直線補間すると、ギャル少女の粗い網目の折れ目が写って、鼻から放射状のしわが出た → 手本の頂点を薄板スプラインでなめらかにつなぐ。
    - 本当の形どおりの法線だと、正面から光を当てたとき鼻のまわりに強い陰としわが出た。ギャル少女も法線を計算し直すと同じ陰が出る（ふだんは粗い網目の法線がなめらかなので控えめに見える）→ 法線を盛り上げる前の顔の向きへ 80% 寄せる。60% ではしわが少し残った。

    - `nosebump.py -- お嬢様.glb 出力.glb 0.0,0.782 gyaru.glb 0.004,0.8148 0.948 0.045 3 4 0.8 orig`
    - 元の小さな鼻は、顔の曲面へ乗せ直す段階で消える（曲面は飛び出た点を外して当てる）。
    - 新お嬢様の顔には生成が彫った凹凸が形として残っていて、元の法線でならして隠してあった。法線を計算し直すと、それが段差やしわになって出た。
      `orig` は元の法線を土台にして、形が変わった分の向きの変化だけを足す。
    - 1P〜4P は絵だけが違うので、4本に同じ数字で掛ける。
  - 確かめ方: 横顔を光ありで描く（鼻の先が顔の線から出ているか）＋ 正面を光ありで描く（しわが出ていないか）＋ 鼻先と色の位置を測る。
- **のっぺらぼうの顔を整える順番**（芸術少女・わんぱく少女、2026年9月23日）
  ```bash
  facefit.py    -- s2.glb f1.glb 箱 0.6 3 ; facefit.py -- f1.glb f2.glb 箱 0.6 3   # 彫られた目・口の凹凸を消す（2回）
  headscale.py  -- f2.glb x.glb 倍率 [起こす角度]                                   # 頭の大きさ（1回目）
  mouthpaste.py -- x.glb 元気少女の鼻.png n.png n.glb 0.0,Z 0.0536 0.0536 "" "" NEWMESH  # 鼻の色
  texpad.py → swaptex.py → skinclean.py -- … 箱 "" "" 目の帯の箱 → swaptex.py           # 顔の肌の汚れを消す
  nosebump.py   -- … 鼻先 gyaru.glb 0.004,0.8148 0.94 0.045 3 4 0.8                    # 鼻の形
  headscale.py  -- … 倍率                                                              # 頭の大きさ（輪郭合わせ）
  skinnormal.py -- … 箱 0.03                                                           # 肌の法線だけならす
  ```
  - **`facefit.py` は、以前は継ぎ目の頂点の片方だけを動かしていた（直した）。**
    肌かどうかを頂点ごとの絵の明るさで決めるので、UV の継ぎ目で分かれた同じ位置の頂点の片方だけが動き、
    顔にすき間が開いた（わんぱく最大 39mm、芸術 20mm）。すき間から奥の髪が見えて目の高さに細い線が出て、光を当てるとでこぼこに見えた。
    絵を何度塗り直しても線が消えなかったのはこのため。直したあとは、ならす前の glb と比べてすき間 0 を確かめる（scratchpad の `crack.py`）。
  - `skinclean.py`（新しく作った）: 顔の前面の肌を肌の色でそろえる。頬の赤み・鼻の色は赤さに応じて残し、前髪は残す。
    目の帯（内側の箱）では、色の割合ではなく「顔の面の上にあるか」で肌か髪かを決める（目の線は細い三角形の中にあって、色では髪と判定された）。
    **`texpad.py` は skinclean の前に掛ける。** 後に掛けると、skinclean が肌の色で埋めた島のふちを灰色で塗り戻した。
  - `skinnormal.py`（新しく作った）: 肌の頂点だけ法線をならす。facesmooth.py の n は前髪の法線までならしてしまう。
    生成の顔は大きな三角形なので、ならさないと光を当てたとき角ばりがでこぼこに見える。σ 0.03 で角ばりが消えた。
  - `facefit.py` で顔をならすと鼻の形も消えるので、鼻を作るのはならしたあと。
- `timezero.py` は、Blender で書き出すたびに最後に掛ける。
  掛けないと、クリップが1コマ後ろにずれ、並び順も変わる。
  preview.html はクリップを番号でそろえるので、元気少女と比べられなくなる。

### 落とし穴：顔が青白くなる（skinmatch の手本の赤が 1.0 のため）

2026年9月23日、「元気少女以外の顔がゾンビっぽい」と指摘されて測った。

| | 顔の肌の色 | **鮮やかさ** | 赤が255で振り切れた割合 |
|---|---|---|---|
| 1P 元気少女 | 231,182,142 | **0.377** | 0.0% |
| 2P お嬢様 | 223,202,190 | 0.130 | 22.6% |
| 3P 秀才少女 | 231,209,199 | 0.118 | 39.7% |
| 4P ギャル少女 | 231,208,183 | 0.205 | 4.1% |

**明るさは4人とも同じ。違うのは鮮やかさだけ。** 色が抜けているので青白く見える。

原因は `skinmatch.py` の手本 **(1.00, 0.82, 0.72) の赤 1.00 が、表せる一番上の値**だということ。
肌の**中央値**をそこへ置くので、中央値より明るい肌は必ず切り捨てられる。
秀才少女・ギャル少女では「明るさ 0.62 以上だけを肌と見る」窓を渡したため、
**一番明るい肌の中央値が 1.0 に置かれ、顔がまるごと潰れた。**

→ **手本の赤には余裕を持たせること。** 三面図の**顔の四角**から測った色をそのまま使えばよい
（三面図ぜんぶの肌から測ると、金髪や赤いスカートが混ざる。実際に混ざった）。

### 直す道具：`skinclip.py`（あとからでも直せる）

```bash
blender -b --factory-startup -P skinclip.py -- 入力.glb 出力.png 手本r,g,b [色相] [鮮やかさ] [明るさ]
blender -b --factory-startup --python swaptex.py -- 入力.glb 出力.png 直した.glb
```

- **緑と青は振り切れていない**（陰影が無傷で残っている）ので、**赤を緑から組み立て直せる**。
  振り切れていない肌で `赤 = a×緑 + b` を当てはめ、潰れた画素の赤を作り直す。
- 計算は**見た目の色（sRGB）のまま**行う。「255で振り切れ」を直接扱えるため。
- **直す場所は3次元で「頭から上」と「脚」に限る。** 色だけで選ぶと、
  秀才少女のチェックの白い升まで茶色くなった（描いて気づいた）。
- **ギャル少女には使えない。** 金髪(228,204,183・鮮やかさ0.202)と肌(231,208,184・0.204)が
  色として同じで、分けられない。直すと髪まで桃色に染まる。
- `swaptex.py` は絵の入れ物だけを差し替えるので、骨24本・動き7本はそのまま残る（突き合わせて確認済み）。

**濃さは描いた絵の「目と目の間」をつまんで決めること。** 三角形の箱から測った中央値だけで
決めたら「赤すぎる」と言われた（ほおの鮮やかさ 0.120。元気少女は 0.099、お嬢様は 0.083）。
手本を 232,192,172 → **234,202,186** に下げて 0.078 にしたら通った。

最終的な手本（2026年9月23日）:

| | 手本の色 | ほおの鮮やかさ |
|---|---|---|
| 秀才少女 | **234,202,186** | 0.078 |
| お嬢様 | **231,196,176** | 0.083 |

## 15. 犬（四足）は、この手順では骨を入れられない

## 16. 四足の骨は Rigify のメタリグを使う

2026年9月22日に確かめた。Blender 5.2 に入っている Rigify（版 0.6.10）に、四足用のひな形がある。

### 使えるひな形

| 追加コマンド | 中身 | 骨の数 |

| `armature_basic_quadruped_metarig_add` | **基本の四足**。背骨・尻尾・前脚・後脚だけ | **34** |
| `armature_wolf_metarig_add` | オオカミ（イヌ科）。顔と指まで入る | 190 |
| `armature_cat_metarig_add` | ネコ。顔と指まで入る | 174 |

デフォルメの犬には要らない。表情はテクスチャの差し替えでやる（女の子と同じ）。

### 本生成（rigify_generate）も画面なしで通る

`basic_quadruped` から生成すると、操作用も含めて283本、
そのうち**変形に使う骨（DEF-）は46本**。Unity に持っていくのはこの46本。

内訳：背骨12（尻尾ふくむ）・骨盤2・後脚（腿/すね/足/指）各2本ずつ・
前脚（肩/腿/すね/足/指）各2本ずつ・胸2。

Rigify が脚に IK を付けてくれるので、四足の走りの動きも足先を置いていくだけで作れる。
手で骨を組むより、こちらが早い。

### 道具：`dogfit.py`（メッシュを測って、骨の座標を出す）

```bash
"/c/Program Files/Blender Foundation/Blender 5.2/blender.exe" -b -P dogfit.py -- 入力.glb 出力.json [そろえたメッシュ.glb]
```

`dog_rig.py` の `BONES` は仮モデルの寸法を手打ちしてあった。メッシュを入れ替えるたびに
測り直すのは手間なので、形から自動で出すようにした。`dog_rig.py` と `dog_run.py` は
3つめの引数にこの JSON を渡すと、そちらを使う。

1. 向きと大きさをそろえる（前を -Y、上を +Z、足を z=0、高さを 0.788 に）
   - 左右＝一番うすい向き、上＝残りのうち長い方、で軸を決める
   - 上下は「足は細いので下半分の頂点が少ない」、前後は「高い所が張り出している側が頭」で向きを決める
2. 前後の位置ごとに体の上端・下端を測り、**その線に沿って背骨を置く**
3. 脚・頭・尻尾を測って `BONES` を組み立てる

**犬種で背中の傾きがまるで違う。** 柴の子犬は胴の中ほどで背中が 0.71、腰で 0.39 まで落ちていた。
背骨を直線で置くと体から飛び出す。

### ハマりどころ（生成メッシュに骨を入れる時）

**12. 自動ウェイトが「成功したのに1本も重みが付かない」。**
生成モデルの glb は UV の切れ目で頂点が分かれている（22,958頂点のうち、
同じ場所に重なっているものを溶接すると 15,613 になった）。
面がつながっていないので熱の計算が解けないが、**例外は出ない**。黙って全部0になる。

対策は、**溶接したコピーで計算して、重みを元のメッシュへ位置で写す**。
溶接は同じ場所の頂点をまとめただけなので、一番近い頂点が元の相手になる（KD木で引く）。
元のメッシュは触らないので UV は壊れない。

```python
tmp = mesh.copy(); tmp.data = mesh.data.copy()     # コピーを作って
bpy.ops.mesh.remove_doubles(threshold=1e-4)        # 溶接して
bpy.ops.object.parent_set(type='ARMATURE_AUTO')    # 重みを計算し
# → KD木で、元のメッシュの各頂点に一番近いコピーの頂点の重みを写す
```

これで 34本すべてに重みが付き、距離で埋める処理も、かたまりごと付ける処理も出番が無くなった。

**13. 「成功したか」は例外ではなく、重みの数で見る。**
`parent_set` は失敗しても例外を投げないことがある。
**重みの付いた骨が0本ならやり直す**、という判定を入れておく。

**14. 脚の付け根は、見えている脚の上端ではなく体の中にある。**
ふさふさの犬ほど、肩と股関節は胴の輪郭よりだいぶ内側。
はじめ「おなかの少し上」に置いたら脚が 0.13 しか取れず、走らせると**胸が地面につくほどかがんだ**。
おなかから胴の深さの 0.33（前）・0.38（後ろ）まで上げると、脚が 0.20 になり走りらしくなった。

走りの沈みは **（脚の長さ）×(1 − BEND·cos SWING)** で決まる。脚を長くすると沈みも深くなるので、
**おなかの高さから逆算して**付け根を決めること。

**15. 接地の端では、肉球を浮かせる。**
脚を振り切った所でつま先が地面にめり込む（実測 -0.020）。実際の犬も、着く時はつま先から、
離れる時はかかとから浮く。`ROLL * (1 - cos θ)` を足すと、めり込みが -0.012 まで減り、
**胴の沈みも 0.046 → 0.028 に浅くなった**（同じ式が両方に効く）。

**16. 歩幅はコマの間も測る。**
16コマだと接地が3コマしか当たらず、歩幅が 0.129 と短く出た（設計値 0.200）。
`sc.frame_set(int(f), subframe=f - int(f))` で1コマを4つに割って測ると 0.153 まで戻った。
設計値も一緒に出しておき、**大きく食い違う時は測り方を疑う**。

### ハマりどころ

**1. `read_factory_settings` を使うと Rigify が無効に戻る。**
アドオンの設定まで初期状態に戻されるので、メタリグの追加コマンドが「見つからない」と言われる。
場面を空にしたい時は、全選択して削除する。

**2. 脚の節は1本に減らす。**
Rigify の既定では1節を2本のDEF骨に割る（`DEF-shin.L` と `DEF-shin.L.001`）。
デフォルメの短い脚には細かすぎて、**すねに重みが1つも付かなかった**（10本が空）。

```python
meta.pose.bones['front_thigh.L'].rigify_parameters.segments = 1   # 前脚・後脚の4本に掛ける
```

DEF骨が46本→34本に減り、重みの付かない骨も10本→4本になった。

**3. 自動ウェイトが届かない骨が残る。**
熱の計算は、隣の骨に挟まれた短い骨を0にすることがある。
`dog_rig.py` の `fill_by_distance` が、骨からの距離で埋めて合計を1にそろえ直す。
仮モデルは球と円柱が重なった作りなので特に苦手だった。本番の生成メッシュでは減るはず。

**4. 脚はまっすぐに置かない。**
ひざを前、飛節を後ろへ少し曲げておく。まっすぐだと IK が向きを決められない。

### 道具：`dog_run.py`（走りと飛びかかり）

```bash
# dog_rig.py が保存した .blend を読む。--factory-startup は付けない
"/c/Program Files/Blender Foundation/Blender 5.2/blender.exe" -b -P dog_run.py -- dog_rig.blend 出力フォルダ
```

**襲歩（ギャロップ）**にした。後脚2本 → 前脚2本 の順に蹴り、その間に**宙に浮く時間**がある。

はじめは速歩（トロット）で作った。ところが**歩幅が 0.02 しか出ず、「パタパタ」としか見えなかった**。
原因は脚の長さ。仮モデルは股関節から足首まで 0.24（前）で、立っている姿がすでに
まっすぐ伸びきっている。足を前後に出すと IK の届く範囲を超えるので、足がその場で止まってしまう。

ギャロップなら地面を蹴っている時間が1周の 1/4 で済む（トロットは 1/2）。
**同じ速さでも、1周をゆっくりにして歩幅を大きく取れる**。

**足首は「股関節を中心にした円の上」に置く。**
これが一番の勘どころ。角度 θ と縮み r を決めて `(−r·L·sinθ, r·L·cosθ)` に置けば、
**IK が届かなくなることが原理的にない**。前後の位置と高さを別々に決めると、必ずどこかで届かなくなる。

**胴の高さは、接地している脚から逆算する。**
脚を θ 度振ると股関節は `L·cosθ` までしか上がれない。接地中の脚の中で一番低いものに合わせる。
こうすると**足が地面で滑らない**（＝1周で進む距離が動きから決まる）。
どの脚も着いていないコマは、宙に浮いた高さ（`AIR`）にする。

その場で走る動きにしてある（前へは進まない）。位置を動かすのは使う側の仕事
（park12.html / Unity）。女の子のクリップと同じ考え方。

| 決めた値 | |
|---|---|
| 1周 | **16コマ／24コマ毎秒 ＝ 0.667秒** |
| 脚を振る角度（`SWING`） | 32度（片側） |
| 接地している割合（`STANCE`） | 0.20 |
| 接地中のひざの曲げ（`BEND`） | 0.93（1.0 でまっすぐ） |
| 宙でたたむ量（`TUCK`） | 0.30 |
| 宙に浮く高さ（`AIR`） | 0.035 |
| 接地の端で肉球を浮かす量（`ROLL`） | 0.12 |
| 胸の反り・首の振り・尻尾 | 2.5度・7度・14度 |
| 着地の順（位相） | 左後 0.00 → 右後 0.06 → 左前 0.40 → 右前 0.46 |

そのあと `nla.bake` で IK の結果を骨そのものの回転へ焼く。

**`SWING` と `STANCE` は組で決める。** 角度を大きくすると歩幅は伸びるが、
同じだけ胴が沈む（→ ハマりどころ14）。沈みを抑えたまま1周で進む距離を稼ぐには、
角度ではなく `STANCE` を小さく（宙にいる時間を長く）する。
仮モデル（脚 0.24）は 42度／0.264 だったが、柴の子犬（脚 0.20）は 32度／0.20 にした。

### 走りを測った結果（柴犬・2026年9月22日）

| 測ったこと | 結果 |
|---|---|
| 脚の長さ（股関節〜足首） | 前 0.203・後 0.220 |
| 歩幅（つま先の前後・接地中） | 後脚 0.188・前脚 0.137〜0.138（設計値 0.208） |
| つま先の最低点 | 0.0110 |
| 体の最低点 | **−0.0117**〜0.0884（少しだけめり込む。高さの1.5%なので見えない） |
| 胴の上下（`torso`） | −0.028〜+0.035 |
| この動きが表している速さ | **1.22 単位/秒**（歩幅 0.163 ÷ 接地 0.133秒） |

最後の1行が大事。**使う側はこの逆数を掛ければ足が滑らない**（1/1.22 = 0.82）。
`dog_run.py` はこの値を最後に出すので、そのまま park12.html の `DOG_RUN_GAIN` に書く。

測り方は、つま先の骨（`DEF-toe.L` など）の先端を1周ぶん追い、
**一番低い所から 0.02 以内にいるコマ＝接地**として、その前後の幅を歩幅とする。
メッシュ全体の平均で測ると4本の足が混ざって、まったく別の数字になる。

### 飛びかかり（Jump）：一発の動き

走りと同じ `dog_run.py` が、続けて飛びかかりも作る（`JUMP_KEYS` の表を書き替えるだけで直せる）。
14コマ・0.583秒。ためる → 蹴る → 伸びて宙に → 前足から着地 → 沈んで受け止める → 立つ。

置き方は走りと同じ「**股関節を中心にした円**」。だから IK が届かなくなることがない。
接地しているコマは、足首の高さ `胴の高さ + L(1 − r·cosθ)` が 0 になるように縮み `r` を選んである。

| 測ったこと | 結果 |
|---|---|
| 体の一番低い所（14コマ） | −0.002〜**0.186**（0 が地面。マイナスならめり込んでいる） |
| 一番高く浮くコマ | 7〜8コマめ（0.25〜0.29秒） |

**はじめ、ためる所と受け止める所で −0.019 めり込んだ。**
足首は 0 に合わせてあっても、**つま先の骨が回って地面より下へ出る**。
その2コマの胴を 0.02 上げると消えた（胴を上げれば、同じだけ足首も上がる）。

### 2つ以上の動きを1つの glb に入れる

Blender は「今の動き」しか書き出さない。**動きは棚（NLA トラック）に上げること。**

```python
tr = rig.animation_data.nla_tracks.new()
tr.name = 'Run'; tr.strips.new('Run', 1, act)
rig.animation_data.action = None          # 次の動きを作る前に、今のを外す
```

書き出しは `export_animation_mode='ACTIONS'`（棚の動きを別々のクリップとして出す）。

**17. 書き出す範囲（`export_frame_range`）を外すと、輪がもたつく。**
走りは輪にするため「最後のコマ＝1コマめ」を1つ余分に打ってある。
範囲を切らないとその17コマめまで出てしまい、クリップが 0.667秒 → **0.708秒**になって、
1周ごとに1コマ分止まって見える。`sc.frame_end = FRAMES` を入れて `export_frame_range=True` で出すこと。

**18. 読み込んだ動きも、出す前に棚へ上げ直す。**
`dogweb.py` のように「読み込む → 加工する → 出す」道具では、読み込んだ動きはアクションになるが
棚には乗らない。そのまま出すと**1つしか出ない**。全部を棚へ上げてから出す。

### ハマりどころ（動きの方）

**6. `.blend` にはメタリグも残っている。**
`next(... type == 'ARMATURE')` で拾うと、本生成した rig ではなく元のメタリグ（34本）を掴む。
**メッシュの Armature モディファイアが指している方**を選ぶこと。

**7. Blender 4.4 以降は `action.fcurves` が無い。**
動きの曲線は層とスロットの中に移った。`AttributeError: 'Action' object has no attribute 'fcurves'` が出る。

```python
def action_fcurves(act):
    if hasattr(act, 'fcurves') and len(act.fcurves): return list(act.fcurves)
    out = []
    for layer in getattr(act, 'layers', []):
        for strip in layer.strips:
            for cb in getattr(strip, 'channelbags', []):
                out.extend(cb.fcurves)
    return out
```

**8. 足の置き場所は、骨の向きへ直してから渡す。**
`pose_bone.location` は世界の向きではない。
`pb.bone.matrix_local.to_3x3().inverted() @ 世界のずれ` で直す。

**9. どの骨にも結ばれない頂点が残る。耳や尻尾の先が取り残される。**
自動ウェイトの熱の計算は、離れた出っぱりに届かない。仮モデルでは **420頂点（4%）** が残り、
動かすと耳の先だけが空中に取り残された。`dog_rig.py` の `fill_orphan_verts` が埋める。

埋め方を2回まちがえた。**頂点ごとに「一番近い骨」や「一番近い頂点」から選ぶと、巻き尾で失敗する。**
尻尾の先はお尻の上に重なっているので、一部の頂点がお尻の骨を掴み、
**そこだけ体へ引っぱられて細く伸びる**。正解は次の2段構え。

1. 辺のつながりで「かたまり」に分ける（仮モデルは風船を並べた作りなので、耳も尻尾の先も別のかたまり）
2. **かたまりごと1本の骨に付ける**（かたまりの中で骨が分かれなければ、伸びようがない）

面をたどって隣から重みを写す手も試したが、**別のかたまりには辺が通っていないので1個も埋まらなかった**。

**10. 見せる前に、必ず1周ぶんの絵を並べて見る。**
数字（歩幅・最低点）が全部よくても、耳が外れている・尻尾が伸びている、は数字に出ない。
`check_run.png` を開いて目で見る。

**11. three.js は「初めて画面に映る時」に絵の描き方を作る。そこで一瞬止まる。**
犬を出した瞬間の1コマだけ **0.25秒**かかり、「犬が出てきたら重くなった」と見えた。
ずっと重いのではなく、**出た瞬間の1回だけ**。測ると、そのコマで作られたプログラムが2つ（本体と影）あった。

読み込みのうちに、**千分の1の大きさにして2コマだけ画面へ描いておく**と、必要な分がすべて作られる。
1画素にもならないので目には見えない。

```js
const was = o.visible, sc = o.scale.clone();
o.scale.setScalar(1e-3); o.visible = true;
renderer.render(scene, cam); renderer.render(scene, cam);   // 本体の分と影の分
o.visible = was; o.scale.copy(sc);
```

**別の入れ物（`WebGLRenderTarget`）へ描くやり方は効かない。** 色の扱いが
`srgb` から `srgb-linear` に変わるので、本番でもう一度作り直しになる（実際にこれで1回はまった）。
読み込んだ直後ではなく、**場面がひと通り描かれてから**呼ぶこと（早すぎると、やはり作り直しになる）。

**5. 書き出しの骨が多すぎる。**
glb には操作用も含めて247本が入る。Unity へ持っていく時は
**DEF- の34本だけに減らす**こと（`stripbones.py` が使える）。

## 17. 動かない置物（老夫婦）は、座った三面図から作る

骨を入れずに、生成したメッシュをそのまま置く。**三面図を座った姿勢で描かせる**のがすべて。

### 手順

1. **イベントの一枚絵を参照画像として渡して**三面図を作る（`gpt_image_2_5` / high / 2k / 3クレジット）
   - これで服の色が確実に合う。言葉だけで色を指定するより速くて確実
   - 「**見えない椅子に座っている**（腿は水平・すねは垂直・足は床）」「椅子や机は描かない」と書く
   - 「三面とも同じ大きさ・同じ高さ・同じ床の線」と書く
2. 白いすき間で3枚に切り分ける
3. `multi_image_to_3d`（`should_texture` だけ・**リグは付けない**・30クレジット）
4. `elderfit.py` で向きと大きさをそろえる
5. `dogweb.py` で軽くする（8千三角形・1024の絵）

### 道具：`elderfit.py`

```bash
blender -b -P elderfit.py -- 入力.glb 出力.glb 高さ つま先のy [確認画像.png]
```

やっていること：高さを合わせ、**足を z=0・左右の中心を x=0・いちばん前（つま先）を指定の y** に置く。
入れ替える時は「つま先」で合わせること。奥行きが変わっても、足の位置がずれない。

確認の絵には**ベンチの座面（0.64）の高さに灰色の板**を出すので、腰が浮いていないか見られる。

### 作った結果（2026年9月23日）

| | 仮モデル | 作り直し |
|---|---|---|
| メッシュ | 23個（球と円柱の組み合わせ） | **2個** |
| 三角形 | 4万 | 1.6万（軽くした後） |
| 描画回数への影響 | — | **148回 → 106回** |

**質を上げたのに軽くなった。** 重さを決めるのは三角形ではなく「別々に描く物の数」なので、
手で組んだ部品の寄せ集めより、生成した1枚のメッシュの方が速い。

### 落とし穴：生成した「座り姿」は、腰が低すぎる

三面図に「腿は水平・すねは垂直」と書いても、出てくる立体は**低い腰掛けに座った形**になりやすい。
足を地面に着けると、お尻の高さは**お爺ちゃん 0.435・お婆ちゃん 0.412**（ベンチの座面は 0.64）。
座面の板がふとももを貫いてしまう。**二人とも同じ症状だった**ので、必ず両方を確かめること。
**総身長を合わせても直らない。** 合わせるべきは身長ではなく**お尻の高さ**で、
そのまま拡大すると身長が 3.0 を超えてしまう（すねが短いため）。

お婆ちゃんは長いスカートが座面を隠すので、しばらく気づかなかった。
**隠れて見えなくても寸法は狂っている**ので、確認の絵の灰色の板で必ず見ること。

骨が無いので、`elderfit.py` に**すねを縦に伸ばす**手を足した（引数をあと3つ足すと働く）。

```bash
# お爺ちゃん
blender -b -P elderfit.py -- grandpa_raw.glb new_grandpa.glb 1.819 -0.942 fit.png 0.12 0.435 0.19
# お婆ちゃん                                                               ↑y0  ↑y1   ↑持ち上げる量
blender -b -P elderfit.py -- grandma_raw.glb new_grandma.glb 1.901 -0.685 fit.png 0.12 0.412 0.21
```

- `y0` より下（靴・足首）はそのまま
- `y0`〜`y1`（すね）を縦に伸ばす
- `y1` より上（腰から頭）は、形を変えずに `lift` ぶん持ち上げる

足は地面に着いたまま、お尻だけが座面へ上がる。そのぶん背は高くなる

座った姿には比べる相手がいないので目立たない。**板が体を貫く方がずっと目立つ。**

前後の位置も「つま先」ではなく**背中**で決める。背中が背もたれに当たる所が正しい位置。
つま先の y は、お爺ちゃん −0.66 → **−0.942**、お婆ちゃん −0.617 → **−0.685** にして前へずらした。
（お爺ちゃんは背中が背もたれの 0.3 も後ろへはみ出していた）

### 道具：`skinmask.py`（どの画素が肌か、一度だけ決めて絵に残す）

そこで、**画素ごとに「肌・髪・服・靴・目口眉」と書いた絵を一度だけ作って残す**。

```bash

```

### マスクを「囲み箱」で塗ってはいけない（2026年9月23日）

最初のマスクは、三角形の **UV の囲み箱**をまるごと塗っていた。隣の三角形の箱と重なるので、
髪のように UV が細かく詰まった所では**四角い塗り残し**ができ、色を直したとき額が斑になった。

→ **三角形が実際に覆う画素だけを塗る**（重心座標。`tintcloth.py` と同じやり方）。これで斑は消えた。
ただし覆う画素だけだと島の外の塗り広げの帯が空白になるので、**最後に4回だけ外へ広げる**。

あわせて顔の決め方も直した：

- 顔は**頭の中心から前を向いた円錐（前から約60度）**。四角い箱だと丸い頬のふちが顔から外れる
- **首とあごを肌に入れる**（服にすると、あごの下に色の境目が出る）
- 顔の中では**はっきり暗い所（目・眉・口）と白目だけ**を分ける。肌らしさの窓だけで分けると
  影になった肌が穴になり、斑に見えた

### 落とし穴：薄い色の服に影を掛けると「汚れ」に見える（2026年9月23日）

### 落とし穴：差し替え用の URL は拡張子まで合わせる（2026年9月23日）

ページは `CDN + ID + ".zip"` で読む。Higgsfield は**アップロード時のファイル名の拡張子**で
URL を作るので、`.glb` という名前で上げると `.zip` の URL は **403** になる。
差し替え用の glb は必ず **`.zip` という名前で上げる**こと（中身は glb のままでよい）。

### 三面図は「文章で描き直させる」と別人になる（2026年9月23日）

芸術少女・わんぱく少女で、候補の絵を**文章で説明して**三面図を描かせたら、
髪型も服も頭身も別物になった。「紫の髪」と書いても、モデルは別の紫を描く。

**正しいやり方は、絵を2枚渡すこと。**

| 渡す絵 | 何が決まるか |
|---|---|
| 選んだ候補（その1人だけ切り出す） | 髪型・髪色・服・小物・色 |
| **既にあるキャラの三面図**（ギャル少女を使った） | **頭身・頭の大きさ・手足の長さ・背の高さ・背景・光・三面の並び** |

2枚目が要る。1枚目だけだと頭身が他のキャラと揃わない。
モデルは `gpt_image_2_5`、`aspect_ratio:"21:9"`、`quality:"high"`、**`resolution:"2k"`**。
2k を指定しないと 1k で出て、貼り直しの見本にするには粗い。

### 持ち物と被り物は、三面図の段階で外す（2026年9月23日）

手に持った物・頭に載せた物は**メッシュに溶接される**ので、あとから外せない。

- わんぱく少女の**帽子**は、書道・水泳・空手などの習い事の場面で邪魔になる → 帽子なしで作り直した
- 芸術少女の**絵筆**、わんぱく少女の**虫取り網**も同じ理由で外した（筆はカバンに挿さった状態だけ残す）
- **生成は途中で止められない。** 気づいた時には38クレジット使い切っている

三面図を描く段階で、**その子が出る全部の場面を思い浮かべてから**持ち物を決めること。

### 腕は三面図の段階で体から離して描く（2026年9月23日）

秀才少女・ギャル少女で起きた「腕が胴と溶接される」は、三面図で腕が体に付いていたのが原因。
**「両腕を体から離し、腕と体の間に背景が見える」**と指定して描かせれば避けられる。

なお「骨の重みで腕と胴の隙間を測る」方法は**判定に使えない**。
溶接されると重みがぼやけるので、溶接された側の方が大きい数字を出すことがある（実際にギャルで出た）。
影絵で測る方法も、頭が大きいキャラでは「二の腕の高さ」がずれて当てにならない。**描いて見るのが確実。**

### 落とし穴：生成すると頭が小さく出ることがある（2026年9月23日）

三面図の頭身をほかの子に合わせても、生成したモデルの頭は小さく出ることがある。
preview も公園も**首の関節の高さ**で大きさをそろえるので、頭が小さいとそのまま小さく見える。
全身を拡大しても、首の高さでそろえ直されるので見た目は変わらない。

**顔の大きさは「顔の輪郭の幅」（髪は入れない）で比べる。** 髪の量はキャラごとに違うので物差しにならない。
正面・平らな光で描き、キャラごとに頭のてっぺんの色（髪）と顔の真ん中の色（肌）を拾って、どちらに近いかで分け、
肌の画素だけの横幅を測る（scratchpad の `facewidth.py`）。固定の色の範囲だと、金髪・オレンジの髪が肌に混ざった。

| 生成して形を整えたあと | 0.282 | 0.295 | 0.291 | 0.293 | 0.244 | 0.177 |

**↑この「一番広い所の幅」だけで合わせたのは失敗だった。**（2026年9月23日）
そのあと芸術を表示 ×0.90、わんぱくを頭 ×1.35 にしたら、ユーザーがグリッドをそろえて4人の画像を重ね、

- **輪郭は「重ねて」合わせる。** preview と同じ縮め方（首の関節 × scaleAdj、足元 0）で4人を正面から描き、
  顔の真ん中から肌をたどって輪郭を取り、高さ 2cm ごとの左右の幅と、あごの高さを比べる（scratchpad の `overlay.py` → `facemask.py`）。
  髪で片側が隠れているキャラ（わんぱく）は、見えている側で比べる。
  全身は、手本を赤・相手を青緑にして重ねると、ずれた所に色が出て分かりやすい（`anaglyph.py`）。
- 合わせる量は2つ。**あごの高さ**は表示の倍率（scaleAdj）で、**顔の幅**は頭の倍率（headscale）で合わせる。
  頭の支点はあごに近いので、頭を大きくしてもあごの高さはほとんど動かない。
- 結果（元気少女：高さ 0.64 で片側 0.147、あごの下端 0.48）

| | 表示（scaleAdj） | 頭の倍率（合計） | 片側の幅（高さ 0.64） | あご（片側 0.03 の高さ） |
|---|---|---|---|---|
| 芸術 | 0.90 → **0.815** | 1.19 → **1.19 × 1.24** | 0.130 → 0.146 | 0.53 → 0.48 |
| わんぱく | 1.0 | 1.35 → **1.35 × 1.19** | 0.122 → 0.144 | 0.49 → 0.48 |

- 輪郭を合わせたら**鼻の高さも比べる**。表示の高さで ギャル 0.601・元気 0.597・芸術 0.608 に対し、わんぱくは 0.627 と 2.6cm 高かった。
  鼻の点を貼る前の段階から、下げて貼り直した。
- 福笑いの初期位置は、輪郭が重なるギャル少女の焼き込み済みの位置を、表示の縮尺で換算して入れる
  （表示 = (モデルの高さ − 足元) × k × scaleAdj、k = 0.438 ÷ (首 − 足元)）。
- **顔を合わせたら、体（横幅・腕の長さ）も比べる。** 顔だけ合わせたら「体が小さい、横幅も腕の長さも」と言われた。
  - 骨の関節の位置を、preview と同じ縮尺で並べて比べる（scratchpad の `joints.py`）。服や髪に左右されない。
    全身の輪郭の重ね（`bodyline.py`）も合わせて見る。

| preview の縮尺で | 元気 | ギャル | 芸術（直す前→後） | わんぱく（直す前→後） |

    - 頭は動かさず、首から下を足元の真ん中を基準に広げる。腕は肩の関節から骨の向きに伸ばす（太さと手は 1+(腕−1)×0.3 倍）。

### 道具：`headscale.py`（頭だけ大きくする）

```bash
headscale.py -- 入力.glb 出力.glb 倍率      # 芸術 1.19、わんぱく 1.64
```

- Head の骨の根元（ほぼあごの高さ）を支点に広げる。首から下・骨・動き・絵には触らない（glb の頂点を直接書き換える）
- Meshy の自動の骨入れは、頭の重みを**襟・肩まで**薄く伸ばしている。重みのまま広げると肩が膨らむので、
  首の関節より下は広げない
- 頭の頂点の多くは首と重みを分け合っている（0.5〜0.99）。重みのまま広げると顔がゆがむので、
  **重み0.6以上は全部同じ倍率**、0.2〜0.6 で徐々に
- 髪が首より下まで垂れているキャラには使わない（髪の先が広がらずに折れる）
- 倍率を決めてから福笑いの位置を決めること（頭の大きさが変わると目の位置も変わる）
- **頭の重みが割れていると、動きの中で頭が縮んだり膨らんだりする。**（2026年9月23日、芸術少女の待機）
  - 芸術少女は後頭部の髪が 頭 0.5・胸（Spine）0.3・肩 に分かれていた（顔の前は頭だけ）。首と胸が動くと後ろ半分だけ遅れ、頭の奥行きが ±7% 変わった。
  - 測り方：待機の各コマで、頭の頂点を頭の骨の向きの座標に直して幅・高さ・奥行きを測る。形が変わらなければ一定（わんぱくは ±1%）。
  - 直し方：`headweight.py 入力 出力 Y0 Y1`（新しく作った）。Y0→Y1 で頭の重みの下限を 0→1 になめらかに上げ、Y1 より上は頭の骨だけ。
    芸術 `0.69 0.735`（首の付け根〜あごの下）。直したあと、奥行きは全コマで一定になった。
  - 仕上げの前に、頭の重みを色にしたモデル（赤=頭だけ）を前・横・後ろから描いて、後頭部が紫（半分）になっていないか見る。
- **大きく広げるときは「あご支点」の方式を使う。**（2026年9月23日、わんぱく少女）
  ```bash
  headscale.py -- 入力.glb 出力.glb 倍率 起こす角度 chin 縦の倍率     # わんぱく 1.6065 10 chin 0.92
  ```
  - 元の方式（Head の根元が支点、頭の重み 0.3 以上だけ広げる）で ×1.6 にしたら、顎の下が横一直線に平らになり「削れて」見えた。
    あごの下の頂点は首と重みを分け合っていて、頭と判定されずに広がらなかったため。
  - あご支点の方式は、顔の真ん中の横顔で「首の前から顔の前へ半分以上出た一番低い高さ」をあごの一番下とし、
    そこより上を全部同じ倍率で広げる。首の関節からあごまでの間でなじませる。頭か体かは頭と首の重みの合計で決める。
  - **起こす角度は付けすぎない。** 15 度だと、あごの平らな裏側が正面から見えた。
    顔の真ん中の線で、あご寄り（0.50）とおでこ寄り（0.70）の前後の差が 元気 +4.1cm・ギャル +3.4cm。わんぱくは 0 度で +6.7、15 度で +2.7 → 10 度にした。
  - **縦の倍率**で頭の長さを合わせる。わんぱくは頭のてっぺんが 0.959（元気 0.912・ギャル 0.920）と長かった → 0.92 倍で 0.925。
  - この方式は法線も回す（元の方式は起こしても法線を回していなかった）。

### ハイハイの動き：`babycrawl.py`（骨を自分で組む。2026年9月23日）

```bash

blender -b --factory-startup -P babycrawl.py -- baby_norm.glb baby_bones.json baby_crawl.glb 確かめ用の絵の先頭名
dogweb.py -- baby_crawl.glb ../../preview/baby_crawl_web.glb 40000 1024     # 面は減らさず、絵だけ 1024（2.05MB）
```

- **犬の Rigify（四足）は使わない。** 「脚で立つ」前提で、赤ちゃんの「手とひざ・すねで床に着く」形に合わない。
  骨は自分で組む 17本（hips・spine・neck・head・tail、upperarm/forearm/hand、thigh/shin/foot の左右）。位置は `baby_bones.json`
- `baby_norm.glb` は生成そのままを「床 z=0・左右と前後の中心 0」にそろえたもの。**生成メッシュは左右が対称でない**（右手は左手より 0.13 前、右脚は外へ開き、左脚は体の下へ入る）ので、骨は左右別々に測る。
  測り方：方眼（0.1 ごと）入りの横・正面・下からの絵、床から 0.06 以下の頂点のかたまり、高さごとの断面。骨を線で重ねた絵で確かめてから使う
- 重みは dog_rig.py と同じ「溶接したコピーで熱の計算 → 位置で写す」。17本すべてに付いた。手首から先は手の骨だけにそろえる
- 動きは「世界の向き」で骨ごとの回し方を決めて `pose_bone.matrix` に入れる（親から順に、1本ごとに `view_layer.update()`）。1周 24コマ＝1秒、床に着いている割合 0.62、右手＋左ひざ／左手＋右ひざ の組

### 顔を整える：`babyface.py`（2026年9月23日）

「顔が薄っぺらく見える・肌が汚い・ひびが入っている」と言われた。原因は2つ（どちらも生成のメッシュ。骨や動きのせいではない。止めた形でも同じに見えた）。

- **絵の継ぎ目で頂点が分かれていて、分かれた頂点どうしで法線が違う。** 大きな三角形（顔は 650 頂点）と合わさって、光を当てるとひびのような線とまだらになった
- **目・口・鼻が彫り込まれていた**（描いた目・口の下に、くぼみと縁の段がある）

```bash
blender -b --factory-startup -P babyface.py -- baby_norm.glb baby_face.glb     # このあと babycrawl.py に baby_face.glb を渡す
```

1. 読み込んだ法線を捨て、同じ位置の頂点を溶接してなめらかな面にする（UV は面の角ごとに残るので絵はずれない）
2. 顔の前面の網目を細かくする（辺を2等分）
3. 顔に3次の曲面（前後 y を 左右 x・高さ z の式で）を当てはめ、**前後だけ**その曲面へ寄せる。正面から見た位置は動かないので、描いた目・口は崩れない。
   くぼみと出っぱりの点は外して当て直す（3回）。箱のふちで強さを 0 へ。あごの下（高さ 0.76 より下）は入れない。**鼻は形を保ったまま、まわりと同じだけ動かす**
4. 押しつぶされたくぼみの壁（後ろ向きか面積のない面）を消す。鼻の裏は消さない

試してやめたこと（どれも絵で見て悪くなった）:

| 方法 | 起きたこと |
|---|---|
| `facefit.py` | 前を向いた頂点だけ動かすので、あごの下で前と下の面が裂けて黒い線。鼻も消えた |
| `skinnormal.py` | 正面の平面で法線を平均するので、あごの下や口の中の向きまで混ざり、頬の下に黒いしみ |
| Smooth（3方向） | 頂点が面に沿って滑り、描いた目の絵が引きずられて崩れた |
| その動きの面に垂直な分だけ | 目のくぼみの縁でしわ |
| 前後だけ Smooth（網目を細かくしても・曲面に寄せた後に軽く掛けても） | くぼみの壁どうしが平均されて、しわ。右目の横に黒い筋 |
| ラプラス平滑化の「体積を保つ」 | 体じゅうの頂点まで動いた |

直す前の glb は `baby_crawl_顔直し前.glb`（preview は `baby_crawl_web_顔直し前.glb`）に残した。

### ↑の `babyface.py` は没。顔の彫りは消してはいけない（2026年9月23日）

### 顔のヒビを消す：`facenormal.py`（形は動かさず、法線だけ。2026年9月23日）

彫りを残したまま「顔面にヒビ」と言われた。**光を切って描くとヒビは無い → 絵ではなく法線のせい。**
生成のメッシュは絵の継ぎ目で頂点が切れていて、切れた頂点どうしで法線が違う（継ぎ目が線に見える）。三角形ごとの法線もそろっていない（継ぎはぎのまだら）。

```bash
facenormal.py -- baby_crawl_ヒビ直し前.glb baby_crawl.glb          # glb を直接書き換える。骨・動き・絵はそのまま
facenormal.py -- baby_crawl_web_ヒビ直し前.glb baby_crawl_web.glb  # ブラウザ用にも同じく掛ける
```

1. 同じ位置の頂点をまとめて、面の向きから法線を計算し直す（切れた頂点も同じ向きになる）
2. 隣どうしで**向きの差が 40 度より小さいものだけ**を平均する（12回）。彫りの縁はまたがないので、口の彫りは残る
3. **鼻と目の中は 2 回だけ**。12 回ならすと、浅い彫り（鼻の盛り上がり・目のくぼみ）の陰が消えた（形だけの絵で目がほぼ見えなくなった）
4. 選ぶのは顔の箱の中の明るい画素（肌）と、位置で決めた目・口。前髪とフードは暗いので外れる

しきい値を 25 度・18 度にしても、目の陰はほとんど変わらなかった（目は回数で守る）。
確かめ方：`facediag`（絵だけ・絵＋光・形だけ）の3段で、光ありにヒビが無いこと、形だけで目・口・鼻の彫りが見えることを見る。

### ひじを曲げずに進む：`babycrawl.py ... straight`（2026年9月23日）

「腕を曲げないで進むことできる？」→ 別の版 `baby_crawl_straight.glb`（preview は `baby_crawl_straight_web.glb`。baby_crawl.html の「腕」で切り替え）。

- 腕は肩から1本の棒として前後に振る（上腕と前腕を世界の向きで同じだけ回す → ひじは曲がらない）。手のひらは床と平ら（手首だけ曲がる）

### 骨と動き（小学生の元気少女）で分かったこと（2026年9月28日）

「全体的に酷い。右腕が折れてる。右腕とポニーテールが引っ付いて、動くたびに顔が引っ張られている。脚が内股で足首が折れてる」と言われた。

- **幼稚園児の動きは、そのままでは移せない。** 幼稚園児の骨の素の姿勢は腰から太ももが前へ26度傾いたかがんだ形で、脚の長い体に移すと中腰・がに股になる。待機の最初のコマを立ち姿の基準にすると待機はまっすぐ立てたが（`animretarget_world.py`）、歩きは足を一本の線の上に置く歩き方で、脚が長いと交差した

- **左右をそろえる。** 「左右の腕の開く角度が違う。幼稚園児の時にあった過ちを繰り返してないか？」と言われた。幼稚園児の待機の最初のコマは左右で違い（上腕13度・太もも18度）、それを写していた。生成したT字の骨は左右対称（上腕0.4度、手首だけ右が9.4度ずれ）
  - 素の姿勢：上腕は手本の左と右（鏡）の平均、右の上腕・前腕・手首は左の鏡写し（scratchpad の `apose_sym.py`）
  - 待機：幼稚園児の待機は体重を片足に乗せて傾くので、左右の腕の開きが違って見える。左右対称に計算で作った（`childidle.py`：息に合わせた胸の上下と肩・腕・頭のわずかな揺れ、腕は体へ12度。20度では手がスカートに入った）
  - 測り方：scratchpad の `armsym.py`（素の姿勢）・`animsym.py`（動きの全コマ。歩きは半周期ずらした反対側と比べる）。腕の左右差 0度、足首 1.2度（生成の骨の元の差）
- 「待機・歩き共に腕の角度+10度くらい必要。待機、腕を後ろにしてるのが変。歩き、足がロボットダンスの歩きみたい」と言われた（2026年9月28日）
  - 上腕の素の向きは手本の左右の平均が後ろへ16度傾いていた → 前後の傾きを0にした（`apose_sym.py`）。腕を体へ寄せる角度は 待機 12→2度・歩き 20→10度
  - ロボットに見えた原因：腰を低くしたままでひざが曲がりっぱなし、腰の一番高いのが両足が着いた瞬間（逆）、足の裏が平らなまま動く
  - `childwalk2.py`：腰を高く（着いた脚がほぼ伸びる）、腰の一番高いのを片足立ちの真ん中に、かかとから着いて（つま先15度上）つま先で蹴る（かかと28度上）、浮いた足は前半でひざを曲げて上げる、腰を左右にひねり浮いた側へ下げる、28コマ
- 「惜しい、歩き、左右の手と足が同じタイミングで出てる」と言われた。腕の振りの式が脚から4分の1周期ずれていた（同じ側の足と手の前後の相関 0.00）。腕は同じ側の脚と逆（足が前＝かかとが着く時に同じ側の腕が一番後ろ）に直し、相関 -0.93。scratchpad の `armleg.py` で、腰から見た足首と手首の前後の位置の相関を測る（－なら正しい）
- 走り（Run）とスキップ（Skip）も計算で作った（scratchpad の `childgait.py -- 入力 出力 run|skip`）。走り：18コマ、両足が浮く時間あり、上体を前へ10度、ひじ80度、浮いた足はかかとを上げる。スキップ：30コマ、片足で着地→同じ足で跳ねる、反対の脚はひざを上げる（足首16cm）、腕は40度
- 「数本髪の毛が引っ張られて動いてるのがある。それは切り取って」と言われた
  - 全クリップの全コマで辺の長さを測り、素の姿勢の1.5倍を超えて伸びる辺に触れる髪の色の面を消した（`hairtrim.py`、32枚）。ポニーテールから腕の方へ伸びていた毛が消えた
  - **消したあとの「離れた小さなかけら」の判定で頭を消しすぎた（19,332頂点）。** 生成のモデルは絵の島ごとに頂点が分かれて保存されていて、辺だけでたどると見た目はつながった面もばらばらに見える。同じ位置の頂点はつながっているとみなすこと（没は `genki_e3_ht_頭を消しすぎ_没.glb`）

  - 首より上で1.5倍を超えて伸びる辺 117 → 0 本。ファイルは `map/elem/genki_e3_hair.glb`（Idle・Walk_Child・Run・Skip）
- 「全体的に両腕が曲がってるのが気になる。RUNは違うのが入ってないか？スキップもロボットダンスみたいな感じになってる」と言われた

- 「走りさ、幼稚園児のものと明らかに違うよね？歩きを速めてるだけにしか見えない。まず、推測じゃなく自分で確認して！スキップもおかしいから！」と言われた（2026年9月28日）
  - **動きを作ったら、手本（幼稚園児）と同じ向き・同じコマ割りで並べて描き、骨の角度を数字で比べること。** 真横の全コマを描く scratchpad の `row.py`、骨の角度（前傾・もも・すね・ひざ・腕・ひじ、真横から見た角度）を全コマ出す `gaitmeasure.py`
  - 比べると手作りの走りは 前傾4度（手本56〜59度）・もも−9〜+57度（手本−36〜+93度）・腕−41〜+21度（手本−115〜+30度）・ひじ51〜57度で固定（手本3〜73度で曲げ伸ばし）。スキップは0.92秒（手本1.42秒＝34コマ）・腕45度（手本±90度、ひじはほぼ伸ばす）と、どれもずっと小さかった
  - 幼稚園児の Skip は68コマで2回分。1回分は34〜68コマ（0コマ目は34コマ目と少し違う）
  - **幼稚園児の走り・スキップを骨の向きで写した**（scratchpad の `kingait2.py -- 入力 手本 出力 クリップ名 始め 終わり コマ数`）
    - 手足：手本の骨の向きを写す。脚は前後の角度だけ写して左右の開きは自分の素の姿勢のまま（内股にしない）。腕の横への開きは手本と自分の大きい方
    - 左右：左と「右を半周期ずらして鏡写しにしたもの」の平均で左を作り、右はその鏡写し（左右差 2度以内）
    - 胴・首・頭：手本の Idle 最初のコマからの回り方を写し、さらに腰〜首の角度が手本と同じになるよう骨盤から上をまとめて前後に回す（差分だけでは Idle が前かがみな分だけ足りず、走り41度・スキップは後ろへ反った。胴から上だけ回すと、おなかで折れて上着が裂けた）
    - 地面：一番低い頂点（靴底）の高さを「手本の高さ÷脚の長さ×自分の脚の長さ」に合わせる。足首の骨で合わせると2.5cm以上浮いた。手本は左右の着地が半周期ちょうどでない（0.27と0.82）ので、左右の平均でなく低い方を使い、着地がコマの上に来るよう始まりをずらす
    - 走りは奇数コマ（11）だと反対の足の着地がコマの間に落ちる → 12コマ（0.5秒）。スキップは手本と同じ34コマ（1.42秒）
  - 辺の伸びの数（1.5倍超）は、大きな動きでは手本の幼稚園児でも 走り2967本・最大69倍 と多い。数を減らすことより、描いて裂け目を見ること（`zoom.py -- 入力 出力 クリップ コマ 骨 x`）
- 「今の頭身だと中学生くらいにみえるな。…足だけを10cm縮めてみて欲しい」と言われた
  - scratchpad の `legshort.py`：足首の少し上（0.13m）〜股関節を高さ方向に 0.787 倍（境目は2cmでなめらかに）、靴はそのまま、胴から上は形を変えずに10cm下げる。腕・手の頂点は重みの割合だけ下げるだけにする（脚と一緒に縮まない）。骨も同じ写し方。身長 1.30 → 1.20m
  - 縮めたら動きは全部作り直す（待機 → 歩き（歩幅・足の上がりは脚の長さ比 0.8 倍）→ 走り → スキップ → 髪の切り取り。髪の高さも10cm下がるので `hairtrim.py` の ZMIN は 0.75）
  - キャラクターツールの大きさ：首 0.804 / 身長 1.200 → scaleAdj 1.84
- 「右腕に引っ張られている髪の毛がまだ１本ある」と言われた
  - 見つけ方：頭の重みを持つ頂点を、頭の骨から見た位置が動くとずれるものとして探す（scratchpad の `pulled.py`）。色だけでは肌や上着の陰も髪に見える
  - ポニーテールの先から右肩へ伸びた三角1枚の毛で、先の頂点に右の前腕の重み0.65が付いていた（最初の髪の重み直しで、腕の重み0.7以上を袖とみなして残した取りこぼし）。`strandcut.py` で消した
  - 右袖には頭の重みが5〜14%混じり、腕を振ると頭に引かれていた → 腕の重み0.7以上で髪の色でない頂点から頭の重みを外した。首と襟の境目・スコートの重みはならした（`wfix.py`）。ファイルは `map/elem/genki_e3_v4.glb`
- 「凄くよくなった！頭身もこれでいこう！ただ、スキップと走り、手首が折れてるのが気になる」と言われた（小学生編の体は脚を縮めた身長120cmで決定）
  - このモデルの手の骨は前腕から55度ずれて付いている（幼稚園児は6度）。手本の手の骨の向きをそのまま写すと、手首が約40度折れた
  - 手は写さず、前腕にまっすぐ付けたままにした（`kingait2.py`）。確かめ方：scratchpad の `wrist.py` で前腕と手の骨の角度を素の姿勢・全クリップで比べ、同じ値ならまっすぐ。ファイルは `map/elem/genki_e3_v5.glb`
  - **骨の向きを写す時は、骨の付き方（前腕と手の骨の角度など）が手本と同じか先に比べること。** 違う所は向きでなく、素の姿勢からの曲がり具合を写すか、親に付けたままにする
- 「塗りのマスクをまた作って塗り直して欲しい、髪の毛（左側頭部に黄色）やリボンに髪の色が入ってるんだ」と言われた
  - 黄色の面を場所で分けると、リボン（体の右側・ポニーテールの結び目、約1000面）と、左側頭部の房（39面）。リボンの茶色は結び目と輪の内側にしみのように入っていた
  - リボンは形で決めた（黄色の面から折れ目20度未満でつながる面へ広げる）。マスク `map/chars/masks/mask_genki_elem_ribbon.png`、道具 `blender/ribbonfix.py`（やり方は masks/作り方.md）
  - リボンの中の茶色 → 黄色、房の黄色（薄い黄色も含む）→ 茶色。前後を同じ向きで拡大して描いて確かめた。ファイルは `map/elem/genki_e3_v6.glb`

## 20. 小学生編のキャラの作り方（元気少女1Pでたどった道の要点、2026年9月28日）

元気少女1P（`map/elem/genki_e3_v7.glb`）で決まったやり方。細かい経緯は19章。**3Dに触る前にこの章と19章を読むこと。**
道具はすべて `Tools/blender/` にある（実行は `blender -b --factory-startup -P 道具.py -- …`）。

### 決まったこと

- 体は**身長120cm**（約3.3頭身）。130cm（約3.6頭身）は「中学生くらいにみえる」と言われ、脚だけ10cm縮めて決まった
- **候補の絵・三面図・生成は130cmで行い、脚を縮めて120cmにする**（体の位置関係をほかのキャラとそろえるため）
- 瞳はブラウンで全員共通
- 動きは 待機・歩き・走り・スキップ の4本。書き出しは**1秒24コマ**

### 手順

**1. 候補の絵（私服5例）→ ユーザーに見せて決めてもらう**
- 年齢と頭身は数字だけでなく**体の位置で書く**（「頭は全身の29%、あご29%・股60%・ひざ78%」）。「3.5頭身」とだけ書くと4.8頭身で出た
- 身長は**130cm**で描かせる
- 袖と服、髪と袖がくっつきそうな服は避ける
- **5点をユーザーに見せ、どれにするか決まってから三面図に進む。** 決まる前に三面図を作らない

**2. 三面図**（21:9 / 2k / high）
- **身長130cmの体で作る。** 120cmの体でいきなり頼むと、手・腰・肩などの位置関係がほかのキャラと合わなくなるおそれがある。120cmにするのは手順7
- **腕はT字（水平）、脚は肩幅に開いてすき間を見せる。** 45度でも鞄に腕がくっついた
- 顔は**立体の人形の描き方**（まぶたの縁・小さな鼻、横顔で鼻とほっぺが前に出る）。平たいアニメ絵の顔は、3Dでも平らで四角くなる
- ただし**輪郭（あご）は候補の絵のまま。**「丸いほっぺを前に」と頼むとあごが四角くなった
- 頭身がばらついたら、出来た三面図を渡して「頭だけ1.3倍」のように直させる
- **3Dにかける前に**、候補の絵と三面図の顔を同じ大きさで並べ、輪郭と横顔を確かめる（形は貼り直しでは直らない）
- **2人目からは、元気少女の三面図（`map/elem/元気少女_小学生_三面図_8_あご細く.png`）を1枚目に渡して土台にし、「体の形・姿勢・各部の位置はそのまま、髪・顔・服だけ2枚目（候補の切り出し）に描き替える」と頼む。**
  お嬢様で、元気少女の三面図を「並べ方・画風だけ」の見本にしたら、ひざが全身の約4%低く・すねが短く・脚が太くなった。「ひざから下だけ長く」と直させてもほとんど変わらなかった。土台にする方法で、あご・肩・腕・ひざ・足の裏の高さがそろった
  - 確かめ方：2枚の前向きを同じ縮尺で横に並べて横線を引く（`Tools/blender/sidebyside.py -- 出力.png 60 880 元気.png 新しい.png`）
- **子どもの体の位置を「股（crotch）」「太もも（thighs）」などの部位の言葉で書くと、生成の安全判定で止まることがある**（お嬢様の三面図で止まった）。「足を肩幅に開いて、両脚の間に背景が見える」のように書く

**3. 3Dにする**（Higgsfield）
- `multi_image_to_3d`：テクスチャあり・骨あり・`pose_mode: t-pose`・`rigging_height_meters: 1.3`・面数3万（38クレジット）
- 貼り直し `meshy_v5_retexture`（9.5クレジット）。文は**600字まで**。貼り直しで髪とリボンの色を取り違えることがある（→ 手順10で直す）

**4. 顔の横幅を元気少女に合わせる**（`headscale_xz.py`、縦はそのまま）
- 生成した頭は横に広く、「頭の縦幅を変えずに横幅を小さく」と言われた。0.90倍と0.85倍を並べて見比べ、**0.90倍に決まった**
- あごの一番下を支点にし、首の関節からあごまでの間でなじませる（首との境目に段を作らない）。襟・肩は広げない
  ```bash
  headscale_xz.py -- 入力.glb 出力.glb 0.90 0 chin 1.1111 1.1111   # 横0.90、縦と奥行きは 1÷0.90 で元に戻す
  ```
- かける時期は**貼り直しのあと・重みを直す前**（元気少女は A5 = `genki_e3_a1.glb` にかけた）
- **倍率は決め打ちしない。生成した顔を元気少女の完成版と同じ縮尺で正面から並べて測り、合わせる倍率をかける**（合っていればかけない）
  - お嬢様は元気少女の三面図を土台にしたせいか、生成の時点で元気少女の直したあとと同じ幅だった。手順どおり0.90倍をかけたら1割細くなり「輪郭が元気少女と違う」「0.9倍を二回行ってないか」と言われた（かけたのは1回だが、結果はかけすぎ）

**5. 重みを直す**（`hairweight.py`）
- T字で骨を入れると、**髪（ポニーテール）や顔に腕の重みが入る** → 髪を頭の骨だけにする
- 確かめ方：腕を下ろす前後で、頭より上の頂点が2mm以上動いた数を数えて0にする

**6. 素の姿勢**（`apose_sym.py`）
- 下ろすのは**上腕だけ**（ひじから先まで合わせると、ひじが折れた）
- 上腕の前後の傾きは0、前腕は上腕とまっすぐ（生成のままだと約10度曲がっていた）
- **右は左の鏡写し**（手本の左右差を写さない）

**7. 脚を縮める**（`legshort.py`、130cm → 120cm）
- 三面図・生成は130cmの体で行い、ここで脚だけ10cm縮める。**どのキャラもこの順番を守る**
- 足首の上から股関節までを縮める。靴はそのまま、胴から上は形を変えずに下げる。腕は脚と一緒に縮めない
- 縮めたら動きは全部作り直す。キャラクターツールの大きさ（scaleAdj）も変わる（手順11）

**8. 動き**
- 待機：`childidle.py`（左右対称。息に合わせた胸の上下）
- 歩き：`childwalk2.py`（腰を高く、かかとから着いてつま先で蹴る、同じ側の手と足は逆に振る）。120cmの体は `28 22.4 4.8 20 10`（歩幅・足の上がりを脚の長さの比0.8倍）
- 走り・スキップ：**幼稚園児の動きを骨の向きで写す**（`kingait2.py`）。手作りでは動きが小さすぎて「歩きを速めてるだけ」「ロボットダンス」と言われた
  ```bash
  kingait2.py -- 入力.glb genki1p_kinder_ref.glb 出力.glb Run 0 11 12     # 走り 12コマ（0.5秒）
  kingait2.py -- 入力.glb genki1p_kinder_ref.glb 出力.glb Skip 34 68 34   # スキップ 34コマ（1.42秒）
  ```
  - 左右は平均して対称にする。脚は前後の角度だけ写す（内股にしない）
  - 上体の傾きは腰〜首の角度を手本に合わせ、骨盤ごと傾ける
  - 手の骨は写さず前腕に付けたまま（このモデルは手の骨が前腕から55度ずれていて、写すと手首が折れた）
  - 地面は靴底の高さで合わせる

**9. 髪と重みの後始末**（動きを全部作ったあと、最後にかける）
- 伸びる髪の房を切る（`hairtrim.py` → `thinhair.py`）。**動きを作り直すと切った毛が戻る**ので毎回最後にかけ直す。脚を縮めたら髪の高さも下がる（`hairtrim.py` の ZMIN 0.85 → 0.75）
- 腕に引っ張られる房を探して消す（`pulled.py` で探す → `strandcut.py`）。色だけでは肌や上着の陰も髪に見える
